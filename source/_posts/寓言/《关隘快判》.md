## 《关隘快判》

> **文献出处说明**：本寓言改编自以下论文：
> Syed Usman Jafri, Sanjay Rao, Vishal Shrivastav, and Mohit Tawarmalani. *Leo: Online ML-based Traffic Classification at Multi-Terabit Line Rate*. In 21st USENIX Symposium on Networked Systems Design and Implementation (NSDI '24), Santa Clara, CA, USA, April 2024.
> 下文以 **[Leo]** 指代该论文，并在关键情节处标注对应章节或概念。

------

大梁国西境有一道铁门关，是南北商旅必经之地。每日有百万商队通过，每队少则十车，多则百车。守关将军最头疼的事，是判断每支商队是否藏有违禁品。

按旧制，所有商队都得在关前停下，由文书抄录货单、随行人数、马匹毛色、车轮痕迹等数十项细节，快马送往三百里外的京城，由刑部高手逐一推敲。这一来一回，最快也要半个时辰。商队排成长龙，从关内排到关外，怨声载道。更麻烦的是，等京城批文回来，可疑商队早跑没影了。

后来，大梁国工部造出了一种“快判亭”。此亭设在关道正中，商队不必停，只需从亭中穿过。亭内有十二级石阶，每级石阶上站一名哨兵，每个哨兵只问一个问题，比如“车轮是否超过三尺”“马匹是否超过十匹”“货箱是否有铁钉”。商队每过一级，根据答案走左道或右道，下一级哨兵便按前一级的结果问下一个问题。十二级走完，最后一名哨兵举起一面旗：红旗放行，黑旗扣留。整个过程不过一呼一吸之间。

这便是最早的“决策树”判关法。但它有个致命缺陷：石阶只有十二级。如果问题需要问十五层，亭子就建不下了。而且每个哨兵只会问一个固定问题，若想换一套判关规则，得把整个亭子拆了重建。

工部有个年轻匠师，名叫李奥。他日夜琢磨，终于想出了三个妙法。

**第一法：哨兵换题。**

李奥把每个哨兵训练成“百事通”。每个哨兵手里握着一本可以随时翻换的册子，册子里写着关隘可能关心的所有问题——车轮、马匹、货箱、人数、时辰、天气、甚至商队首领的靴子颜色。同时，他面前还摆着一排木牌，每块木牌上写着一个判断阈值，比如“三尺”“十匹”“五箱”。哨兵根据当日将军下发的指令，从册子里挑一个问题，从木牌里挑一个阈值，再发问。这样，同一个哨兵，今天问车轮，明天可以问马匹；今天阈值三尺，明天可以五尺。整座亭子不用拆改，只需换册子和木牌，便能切换成另一棵完全不同的判断树。

**第二法：三问并一表。**

石阶级数仍然有限，李奥便想：何必每级只问一个问题？他把连续三个哨兵编成一组，称为“三问组”。三问组的三名哨兵同时发问，各自得出“是”或“否”。三人的答案合起来共有八种组合。李奥在每组后面挂一张“结果表”，表中预先写好了八种组合分别对应下一步该往哪走。这样，原本需要三级石阶才能问完的三个问题，现在一级石阶之内就同时问完，再由结果表瞬间查出方向。十二级石阶，便相当于能问三十六层问题。若把五个哨兵编成一组，一级石阶能问五层，十二级便能问六十层。组越大，石阶越省，但每组占的地方也越大。李奥反复权衡，最终选了三问一组，恰好够用。

**第三法：双树轮换。**

将军的判关规则常变。以前改规则，必须让整座亭子停工半日，商队又堵成一片。李奥在亭子地下挖了两个暗室，各藏一套完整的哨兵册子和结果表。平时只用甲室，乙室空转。若要换规则，工匠悄悄在乙室中布置新册新表。布置妥当后，只需将入口处一块木牌翻个面——从“甲”翻到“乙”——所有商队便瞬间改走乙室。甲室再慢慢更新，等待下一次轮换。翻牌只需一瞬，商队毫无察觉。

李奥将这三法合在一处，造出了“李奥快判亭”。亭子落成那天，将军亲自测试。他让人扮成商队，有的车轮三尺一，有的马匹十一匹，有的货箱带铁钉……百万商队如流水般穿过，哨兵们翻册换牌，三问组同声发问，结果表瞬间指路，双暗室悄然轮换。一整日下来，无一处拥堵，无一次误判。将军大喜，问李奥：“此亭可判多少种商队？”李奥答：“只要将军给出一个范围——最深问多少层、最多扣多少队、能用哪些问题——此亭便能支持这个范围内的一切判法。而且随时可换，永不停工。”

后来，刑部高手从京城赶来，站在亭外看了半日，叹道：“我在京城推敲一案，需半个时辰。此亭一呼一吸间，已判百万商队。更可怕的是，它判得几乎和我一样准。”

**文献核心创新点解释**

这个故事对应的是 Leo 系统——一种在多太比特线速下于可编程交换机数据平面运行决策树推理的在线流量分类方案。

| 故事元素                                                 | Leo 论文中的概念                                             |
| :------------------------------------------------------- | :----------------------------------------------------------- |
| **铁门关每日百万商队**                                   | 多太比特线速网络流量，需要逐包在线分类。                     |
| **旧制：送京城刑部推敲，半个时辰往返**                   | 控制平面或远程服务器推理，延迟高，带宽瓶颈，无法满足线速。   |
| **快判亭：十二级石阶，哨兵逐级问问题**                   | 传统决策树到 PISA 流水线的自然映射：每个树层级占一个流水线阶段。阶段数有限，树深受限。 |
| **石阶只有十二级**                                       | 可编程交换机流水线阶段数有限（约 10-12 级）。                |
| **哨兵只会问固定问题，换规则要拆亭**                     | 现有方案缺乏运行时编程能力，更新模型需重启交换机或重新编译。 |
| **李奥第一法：哨兵换题（册子+木牌）**                    | **决策树节点多路复用**：每个内部节点用多路复用 ALU 实现，特征可从集合 F 中运行时选择，约束可从存储中运行时选择。一棵代表树可支持整个 (D,L,F) 类。 |
| **李奥第二法：三问并一表**                               | **子树扁平化与多路复用**：将大小为 k 的子树打包，用 k 个多路复用 ALU 并行计算，再用布尔表（SRAM/TCAM）查结果。每层只需一个子树的多路复用单元，而非每个节点一个 ALU。流水线阶段数降为 \([D / \lceil \log_2(k) \rceil] + 1\)，而非 \(D+1\)。 |
| **三问组、五问组，组越大越省石阶但占地方**               | 子树大小 k 的权衡：k 越大，阶段越少，但每层消耗更多 ALU/头部字段资源。论文中通常取 k=3。 |
| **结果表预先写好八种组合**                               | 布尔表编码子树所有输出组合，可用 SRAM 或 TCAM 实现。         |
| **双暗室轮换，翻牌即切换**                               | **运行时编程与双缓冲树状态**：控制平面在非活动树中配置新树，原子切换活动树 ID，避免瞬态不一致，无需停机。 |
| **将军给出范围：最深多少层、最多扣多少队、能用哪些问题** | Leo 抽象 \((D,L,F)\)：最大深度 D、最大叶子数 L、特征集 F。Leo 编译器为代表树分配资源，保证类内任意树均可运行时切换。 |
| **李奥答：此亭支持范围内一切判法，随时可换，永不停工**   | Leo 的核心目标：运行时可编程、资源高效、支持整个决策树类。   |
| **刑部高手：判得几乎和我一样准**                         | Leo 在真实 IDS 数据集上达到接近控制平面离线分类器的精度。    |
| **一呼一吸间判百万商队**                                 | Leo 在 Tofino 交换机上实现线速分类，延迟约 500 纳秒，比控制平面快 500 倍。 |

**与 IIsy 的对比**：故事中若有一个“每级只问一个固定问题、但把所有可能答案组合都写成一本巨册”的旧方案，那便是 IIsy。它虽解耦了树依赖，但组合表随特征数指数增长，内存需求爆炸。Leo 通过多路复用和子树扁平化，将内存需求降为多项式级，从而支持更深的树（SRAM 深度 10，TCAM 深度 22 带叶约束），而 IIsy 仅能支持深度 5（SRAM）或 10（TCAM）。

**一句话总结**：Leo 让交换机数据平面像一座可随时换规则、并行问三题、双树无缝切换的快判亭，在百万商队穿行的线速下，做出接近京城刑部高手的判断。
