## 《快哨与明镜》

> **文献出处说明**：本寓言改编自以下论文：  
> Yutao Dong, Qing Li, Kaidong Wu, Ruoyu Li, Dan Zhao, Gareth Tyson, Junkun Peng, Yong Jiang, Shutao Xia, and Mingwei Xu. *HorusEye: A Realtime IoT Malicious Traffic Detection Framework using Programmable Switches*. In 32nd USENIX Security Symposium (USENIX Security '23), Anaheim, CA, USA, August 2023.  
> 下文以 **[HorusEye]** 指代该论文，并在关键情节处标注对应章节或概念。

边关有座城，叫“物联城”。城里住着千家万户，有看门的摄像头、报信的传感器、传令的智能网关。城不大，但每天进出的商队却多如牛毛，成千上万，络绎不绝。

城门口原先只有一道关卡，设在城内的“中枢衙门”。所有商队进城，都得先到衙门登记、查验、等批文。衙门里的人手有限，商队一多就排成长龙，从城门口一直堵到十里外。更麻烦的是，有些奸细混在商队里，等衙门慢慢查完，他们早溜进城干完坏事跑了。

后来，城主请来一位工匠，名叫霍鲁斯。霍鲁斯说：我有两件宝贝，一件叫“快哨”，一件叫“明镜”。快哨设在城门口，明镜设在衙门里。两件合起来，奸细一个也跑不掉，商队还不堵。

### 一、快哨

快哨是一座小亭，立在城门正中央。商队不必停，直接从亭中穿过。亭子里站着几个哨兵，每人手里拿着一本“白名单”，上面写满了正常商队的特征范围。比如：“骆驼三到五头、货箱四到六只、毛色棕黄、蹄印深浅适中”之类。商队经过时，哨兵飞快地扫一眼，符合白名单的直接放行；不符合的，就在商队尾巴上系一根红绳，让它去衙门里的明镜司报到。

白名单只有薄薄几页，哨兵看一眼就能判断，所以商队穿亭而过，一呼一吸之间就过去了。**[HorusEye §3 Overview]**

但白名单是怎么来的呢？这就要说到城外的“林间哨兵”。

### 二、林间哨兵

城外有一片树林，林子里住着上百个“问树老人”。每个老人手里拿着一串问题，专门用来盘问商队。比如，第一个老人问：“货箱是否超过五只？”超过的走左边，不超过的走右边。然后左右两边各有一个老人接着问下一个问题，比如“骆驼是否超过四头？”这样一层一层问下去，直到每个商队都被问到一个“小格子”里。**[HorusEye §4.1 iForest]**

这些小格子，就是“问树老人”们把整个商队特征空间切成的许多小块。每个小格子里，所有商队的“可疑程度”都是一样的。有的格子全是正常商队，有的格子全是可疑商队。

霍鲁斯把所有老人的问题边界收集起来，合并成一张更大的格子图。然后，他挑出那些“全是正常”的格子，写成白名单规则，交给快哨的哨兵。**[HorusEye §4.1 Rule Generation]**

但有个麻烦：老人问问题时用的是带小数的尺子，比如“货箱是否超过五只半”。快哨的哨兵不认小数，只认整数。霍鲁斯便把所有的边界都向下取整，比如五只半变成五只。他算过，这样取整不会把任何整数商队分错格子。**[HorusEye §4.1 Theorem 1]**

就这样，快哨拿到了一份薄薄的白名单，却能覆盖林间哨兵们辛苦问出来的绝大多数正常商队。

### 三、突发与双向

商队不是一个个单独来的，而是一阵一阵来的。有时候，一队骆驼刚过去，紧接着又来一队，中间几乎不停。霍鲁斯把这种“连续不断、间隔极短”的一串商队叫作“突发”。**[HorusEye §4.2.1 Burst Segmentation]**

快哨要判断一个突发是否可疑，就得看这个突发里商队的数量和货箱大小。但商队有来有回，去程和回程是两拨人。怎么把去程和回程对应起来呢？霍鲁斯想了个妙法：把商队的“来源、去向、货物”等信息拆成两半，用异或运算拼在一起。这样，去程和回程的商队会算出同一个编号，哨兵一查就知道它们是一对。**[HorusEye §4.2.2 Bi-hash]**

可编号有时会撞车。两个不同的商队算出同一个编号，就像两个人同名同姓。霍鲁斯又设了两张登记表。第一张表撞了，就查第二张表。两张表一分，撞车的概率一下子降了十倍。**[HorusEye §4.2.3 Double Hash Table]**

有了突发特征和双向匹配，快哨就能在商队穿亭的一瞬间，判断出它是不是可疑。**[HorusEye §4.3 Complexity]**

### 四、明镜

快哨虽然快，但它的白名单是从正常商队里学来的，遇到从没见过的奸细，有时会拿不准。于是，被系上红绳的商队会被送到衙门里的“明镜司”。

明镜司里坐着一位“明镜先生”。他有一面奇特的镜子，叫“自编码镜”。这面镜子有个本事：你让它照一个正常商队，它能把商队的样子分毫不差地映出来；你让它照一个奸细，它映出来的就歪歪扭扭，怎么看怎么不像。**[HorusEye §5 Magnifier]**

明镜先生先让镜子看了成千上万个正常商队，学会了“正常”长什么样。然后，每当有可疑商队送来，他就用镜子照一照。映出来的样子和原样差得越远，就越可能是奸细。**[HorusEye §5.1 Asymmetric Autoencoder]**

但镜子不能太笨重，否则照得慢，衙门又堵了。明镜先生把镜子做成了“非对称”的：照进去的时候仔细看，映出来的时候粗略画。这样既看得准，又画得快。**[HorusEye §5.1]**

他还用了三种省力的妙法。第一种叫“分步看”：先只看每个货箱的轮廓，再看货箱之间的搭配，两步并一步，省力不少。**[HorusEye §5.2 Separable Convolution]** 第二种叫“隔点看”：不盯着每一个细节，而是隔几个点看一眼，这样一眼能看很宽，却不用多花力气。**[HorusEye §5.3 Dilated Convolution]** 第三种叫“粗尺子”：把原来精细的刻度换成粗刻度，量得没那么准，但快了很多。**[HorusEye §5.4 Model Quantization]**

就这样，明镜先生虽然照得比快哨慢，但比中枢衙门的老文书快得多，而且判得准。

### 五、双关合璧

快哨和明镜配合起来，效果惊人。

每天百万商队穿城而过，快哨直接放行了七成六，只把两成四的可疑商队送进衙门。**[HorusEye §1]** 衙门不再堵了。而明镜先生仔细照过之后，真正的奸细几乎一个不漏——十成里能揪出九成九。**[HorusEye §1]** 剩下那一点点，也翻不起大浪。

霍鲁斯把快哨和明镜合称为“霍鲁斯之眼”。他说：快哨靠的是林间哨兵们问出来的白名单，明镜靠的是自编码镜的照妖本领。一个在城门，一个在衙门，一个快，一个准。两下里一合，物联城从此安宁。

有人问霍鲁斯：为什么不把所有商队都送进衙门，让明镜先生一个个照？霍鲁斯摇头：衙门就那么大，明镜先生就一个，全送进去，商队又堵到十里外了。快哨的作用，就是把大多数正常商队挡在衙门之外，让明镜先生只照那些真正可疑的。

又问：那为什么不把明镜先生搬到城门口？霍鲁斯笑了：城门口风大，明镜先生那面镜子精贵，经不起风吹日晒；而且城门口要的是快，明镜先生照一面镜子要花的时间，够快哨放行几百个商队了。

后来，霍鲁斯把快哨和明镜的做法写成一本书，叫《双关截流》。书里说：守城如守水，不能只堵不疏。快哨是筛子，明镜是滤网。筛子眼大，滤掉大石头；滤网眼细，滤掉小沙子。两下里一配，水既流得畅，又清得净。

**概念解释：HorusEye**

HorusEye 是一个两阶段物联网异常检测框架，旨在实现高吞吐量和高精度的恶意流量检测。第一阶段在可编程交换机数据平面上运行，第二阶段在控制平面上运行。

**故事中的隐喻对应表**

| 故事元素                                 | HorusEye 论文中的概念                                        |
| :--------------------------------------- | :----------------------------------------------------------- |
| **物联城**                               | 物联网（IoT）网络。                                          |
| **商队**                                 | 网络流量/数据包。                                            |
| **奸细**                                 | 恶意流量/攻击。                                              |
| **中枢衙门**                             | 控制平面（传统检测部署位置），吞吐量有限。                   |
| **快哨**                                 | **Gulliver Tunnel**——数据平面上的第一阶段检测，线速过滤正常流量，标记可疑流量。 |
| **明镜司 / 明镜先生**                    | **Magnifier**——控制平面上的第二阶段检测，使用轻量级自编码器进一步分析可疑流量。 |
| **林间哨兵 / 问树老人**                  | **iForest（孤立森林）**——无监督异常检测模型，由多棵 iTree 组成。 |
| **问树老人问问题**                       | iTree 在特征空间中随机选择特征和阈值进行分支。               |
| **小格子**                               | **超立方体（Hypercube）**——iTree 将特征空间划分成的小区域。  |
| **合并所有老人的问题边界，形成大格子图** | **iForest 超立方体聚合**——将所有 iTree 的分割边界合并，形成更细的超立方体。 |
| **每个格子内可疑程度一样**               | **标签一致性（Label Consistency）**——聚合后的 iForest 超立方体内所有样本具有相同的异常评分。 |
| **把“全是正常”的格子写成白名单**         | **白名单规则生成**——将正常超立方体转换为数据平面可执行的白名单匹配规则。 |
| **边界向下取整**                         | **整数化边界**——数据平面不支持浮点运算，将分支阈值向下取整为整数，证明不影响整数数据点的分类。 |
| **突发**                                 | **突发（Burst）**——连续发送且间隔小于阈值的一串数据包。      |
| **突发分段**                             | **Burst Segmentation**——将长突发分割成短片段，降低资源占用。 |
| **去程和回程对应**                       | **双向流匹配（Bi-directional Flow Matching）**。             |
| **异或运算拼编号**                       | **Bi-hash**——用 XOR 将五元组哈希拆成两个哈希的异或，使双向流映射到同一地址。 |
| **两张登记表**                           | **双哈希表（Double Hash Table）**——两个哈希表减少哈希冲突。  |
| **自编码镜**                             | **自编码器（Autoencoder）**——学习正常数据的重建，异常数据重建误差大。 |
| **非对称**                               | **非对称自编码器（Asymmetric Autoencoder）**——编码器更深，解码器更浅，减少参数。 |
| **分步看**                               | **可分离卷积（Separable Convolution）**——深度卷积+逐点卷积，降低计算量。 |
| **隔点看**                               | **空洞卷积（Dilated Convolution）**——扩大感受野而不增加参数。 |
| **粗尺子**                               | **模型量化（Model Quantization）**——将浮点参数转为低精度整数（如 int8），提高吞吐量。 |
| **快哨放行七成六**                       | **流量卸载率 76%**——数据平面过滤掉 76% 的正常流量，减轻控制平面负担。 |
| **十成里揪出九成九**                     | **检测率 99%**——Gulliver Tunnel 在数据平面上检测到 99% 的异常。 |
| **城门口风大，明镜精贵**                 | **数据平面资源受限**——可编程交换机只支持简单指令，无法直接部署复杂深度模型。 |
| **《双关截流》**                         | **HorusEye 两阶段框架的核心思想**——数据平面快速筛查 + 控制平面精确检测。 |

**核心创新点总结**：

1. **两阶段检测框架**：数据平面快速筛查（Gulliver Tunnel）+ 控制平面精确检测（Magnifier），兼顾吞吐量与精度。
2. **首次在可编程交换机上部署无监督 iForest 模型**：提出规则生成算法，将 iForest 转换为白名单匹配规则，仅需整数运算，可在数据平面执行。
3. **轻量级突发特征提取**：突发分段、bi-hash 双向流匹配、双哈希表，在有限交换机资源下实现 O(1) 复杂度的特征提取。
4. **轻量级控制平面模型 Magnifier**：非对称自编码器 + 可分离卷积 + 空洞卷积 + 模型量化，实现百万级包/秒的吞吐量。
5. **优越的性能**：单端口 100Gbps 线速检测，异常召回率 99%，卸载 76% 正常流量，检测性能优于 Kitsune 和 Mousika。vv
